## 2. 결론

현재 문제는 단순히 숫자가 큰 것이 아니다. 서로 다른 시스템이 같은 규모를 공유하지 않아 플레이어가 금액의 의미를 잃는 것이 핵심 문제다.

권장 결론은 다음과 같다.

1. 모든 개인 경제 단위를 원으로 통일한다.
2. 코인을 폐지하고 `증권계좌 예수금`을 원 단위로 둔다.
3. 개별 부동산은 3천만원부터 4,500억원 범위로 제한한다.
4. 조 단위는 한 채의 가격이 아니라 여러 부동산, 주식, 기업지분을 합친 총자산에서 처음 나타나게 한다.
5. 대출은 건물에 귀속시키고 실제 이자를 매월 납부하게 한다.
6. 평판은 돈으로 무제한 구매하는 제2의 화폐가 아니라 행동과 성과를 누적한 신뢰 지표로 바꾼다.
7. 주식은 부동산 후반과 겹쳐 시작하고, 기업은 증권시장 경험과 금융자산을 조건으로 시작한다.
8. 기존 저장 데이터는 일괄 초기화하지 않고 진행 단계와 경제가치를 보존해 이전한다.

## 3. 개편 전 코드에서 확인한 기준선

### 3.1 시작 경제

| 항목 | 현재 값 |
|---|---:|
| 스토리 완료 현금 | 200만원 |
| 시작 건물 | 청주 1번, 시가 3,000만원 |
| 직장 월급 | 월 300만원 |
| 부업 1회 | 1만원 |
| 퇴사 보상 | 3,000만원 |
| 하루 진행 | 실제 5초 |

근거 코드:

- `Player.completeStory()`
- `SettlementService.MONTHLY_JOB_SALARY`
- `GameService.SIDE_JOB_REWARD`
- `Player.resign()`
- `app.js`의 `TICK_DURATION_MS`

### 3.2 부동산 규모

현재 부동산은 3,000만원 원룸에서 10조원짜리 반포 주거 자산까지 증가한다. 최고 건물 한 채가 시작 건물의 약 33만 배다.

현재 연간 표면수익률은 청주 1번 12%에서 서울 4번 3.24%까지 낮아진다. 수익률이 낮아지는 방향은 타당하지만 다음 명칭과 가격 조합은 몰입을 해친다.

- 부산 21층 빌딩: 35억원
- 부산 35층 빌딩: 45억원
- 서울 주거 자산: 10조원
- 전용기: 500억원

즉 전용기 200대와 주거 자산 한 채가 같은 값이 된다.

### 3.3 매매 차익

`ValuationStatus`는 저평가 80%, 시장가 100%, 고평가 120%다. 저평가 매물을 산 뒤 고평가로 매각하면 시장가격 변화가 없어도 매입가 대비 50%의 차익이 가능하다.

현재 거래세와 중개비는 없다. 따라서 시간 경과에 따른 투자보다 평가 상태 재추첨이 더 강한 수익원이 될 수 있다.

### 3.4 대출

현재 대출 규칙은 다음과 같다.

- 매입가의 60% 대출
- 총 상환액은 원금의 120%
- 6개월로 나눈 `monthlyPayment` 저장
- 대출 한도는 `max(1,000만원, (평판 + 1) × 10만원)`

그러나 월 정산에서는 실제 상환액을 현금에서 차감하지 않는다. 6개월이 지나면 평판을 절반 잃고 만기를 다시 6개월 연장한다. 대출은 건물과도 연결되어 있지 않다.

결과적으로 현재 대출은 정상적인 원리금 상환이 아니라 평판을 비용으로 쓰는 무기한 레버리지다.

### 3.5 평판

현재 최종 칭호 조건은 평판 5억이다. 월세를 받는 건물 한 채는 월 1~5 평판을 준다. 기부는 30만원당 평판 1, 사치품은 같은 돈의 1.5배 효율이다.

전체 사치품 가격은 684억 5,030만원이고, 전부 구매해도 얻는 평판은 205만 3,509다. 서울 첫 해금 조건 4,000만의 약 5.1%다. 나머지를 기부만으로 채우면 수조원이 필요하다.

또한 `1조클럽`, `대한민국 상위 5%` 같은 칭호는 실제 순자산이 아니라 평판 숫자로 결정된다. 표시 문구와 판정 기준이 다르다.

### 3.6 비서 비용

모든 비서의 기본 월급은 200만원이다. 숙련도에 따라 복리로 인상되어 숙련도 30의 월급은 한 명당 약 1억 1,208만원이다.

비서 월급은 잔액 확인 없이 현금에서 직접 차감된다. 따라서 현금이 음수가 될 수 있다.

호감도 1부터 30까지 선물만 사용하면 비서 한 명당 약 700억원, 여섯 명이면 약 4,200억원이 필요하다. 후반 자금 회수 장치로는 작동하지만 선물 한 개 가격과 효용의 대응은 약하다.

### 3.7 주식 단위

현재 주가는 1만 9천~11만 8천 코인이고 `1코인 = 100원`이다. 경제적 의미로는 한 주가 190만~1,180만원이다. 그래서 현실적인 주가처럼 보이는 숫자와 실제 구매력이 일치하지 않는다.

현금과 코인을 100:1로 교환하는 과정은 투자계좌 분리에는 도움이 되지만, 코인이라는 명칭과 배율은 주식의 현실감을 낮춘다.

## 4. 재설계 원칙

### 4.1 금액이 아니라 자산의 합으로 성장시킨다

초반에는 한 채의 가격이 곧 플레이어의 자산 규모다. 후반에는 다음 합계가 부를 나타내야 한다.

```text
순자산 = 개인현금
       + 증권계좌 예수금
       + 보유주식 평가액
       + 보유부동산 평가액
       + 비상장·상장 회사 지분가치
       - 남은 대출원금
```

한 채의 가격을 10조원으로 만드는 대신 2,000억원대 건물 여러 채, 수천억원의 주식, 기업지분을 합쳐 조 단위에 도달하게 한다.

### 4.2 세 계좌를 분리한다

| 계좌 | 단위 | 용도 |
|---|---|---|
| 개인 현금 | 원 | 부동산, 소비, 기부, 개인 지출 |
| 증권계좌 예수금 | 원 | 주식 매수·매도·배당 |
| 회사 현금 | 원 | 회사 매출, 비용, 투자, 차입, 배당 |

계좌는 분리하지만 환율은 없다. 개인 현금 1억원을 증권계좌로 옮기면 예수금도 1억원이다.

### 4.3 실제 사실처럼 보이는 표현은 실제 지표로 판정한다

- `1조 자산가`: 순자산 1조원 이상일 때만 표시
- `대주주`: 실제 지분율 기준
- `흑자기업`: 실제 누적 또는 최근 실적 기준
- 평판 칭호: 자산 규모를 단정하지 않는 명칭 사용

### 5.1 임대 운영비

MVP에서는 새로운 관리비 화면을 만들지 않는다. 월세를 받을 때 임대료의 10%를 운영비로 함께 차감해 기록한다.

```text
월 임대수입 = 비서 보너스가 적용된 월세
월 운영비 = 월 임대수입 × 10%
월 순임대수입 = 월 임대수입 - 월 운영비
```

수리비는 기존 랜덤 수리 이벤트로 별도 처리한다. 운영비와 수리비를 합치지 않는다.

### 5.2 평가와 거래비용

| 항목 | 현재 | 권장 |
|---|---:|---:|
| 저평가 | 80% | 90% |
| 시장가 | 100% | 100% |
| 고평가 | 120% | 110% |
| 매수 부대비용 | 없음 | 체결가의 1.5% |
| 매도 비용 | 없음 | 매도가의 1.0% |

저평가 매수 후 고평가 매도의 이론상 가격 차이는 약 22.2%다. 매수·매도 비용 적용 후 순수익률은 약 19.2%이며 거래 쿨다운이 함께 적용된다.

### 5.2.1 도시별 최초 구매 정부지원

청주·세종·대전·부산에서는 도시별 첫 유상 건물 취득의 실제 매입가를 50% 감면하고,
인천은 40% 감면한다. 서울은 지원하지 않는다.

- 무료로 지급되는 청주 시작 건물은 지원 횟수를 소모하지 않는다.
- 일반 매물과 경매 낙찰에 같은 규칙을 적용한다.
- 대출 한도와 매수 부대비용은 감면된 실제 매입가를 기준으로 계산한다.
- 경매 패찰은 취득이 아니므로 지원 횟수를 소모하지 않는다.
- 기존 저장 데이터에서 해당 도시에 유상 취득 건물이 있으면 이미 사용한 것으로 이전한다.

지원은 반복 수입을 영구적으로 높이지 않고 다음 도시의 첫 진입 자본만 낮추는 장치다.

### 5.3 경매

경매는 하루 진행마다 2% 확률로 발생한다. 입찰 조건은 다음과 같다.

| 입찰가 | 낙찰 확률 | 의미 |
|---:|---:|---|
| 감정가 95% | 70% | 안정 입찰 |
| 감정가 88% | 35% | 일반 입찰 |
| 감정가 80% | 10% | 공격 입찰 |

낙찰 건물에도 매수 부대비용 1.5%를 적용한다. 실패 시 원금은 환불하되 입찰가의 1%는 보증비로 반환하지 않는다.

### 5.4 보유 부동산 평가액

현재 보유 건물의 `marketPrice`는 구매 뒤 변하지 않는다. 장기 보유와 평가손익을 만들기 위해 도시별 부동산 지수를 둔다.

```text
도시지수 초깃값 = 10,000
현재평가액 = 카탈로그 기준가 × 현재도시지수 / 10,000
평가손익 = 현재평가액 - 매입가
```

- 지수는 게임월마다 한 번만 변경한다.
- 일반 월 변동은 -0.6~+0.6%로 제한한다.
- 부동산 호재·악재가 있으면 추가로 최대 ±1.5%를 반영한다.
- 한 달 총변동은 ±2.0%를 넘지 않는다.
- 지수 누적 범위는 7,000~16,000으로 제한한다.
- 매물의 저평가·고평가는 현재평가액을 기준으로 계산한다.

`OwnedBuilding`에 계속 시장가를 복사해 갱신하기보다 `baseMarketPrice`와 도시지수를 조합해 조회하는 편이 원장 오류를 줄인다. 기존 부동산 뉴스는 매물 평가확률뿐 아니라 다음 월 도시지수에도 영향을 주도록 연결한다.

## 6. 대출 재설계

### 6.1 데이터 구조

대출은 반드시 한 건물에 귀속한다.

```text
Loan
- playerId
- ownedBuildingId
- originalPrincipal
- remainingPrincipal
- annualInterestRateBasisPoints
- remainingMonths
- delinquentMonths
- status
```

한 건물에는 활성 담보대출 하나만 허용한다. 건물을 팔 때 해당 대출을 먼저 상환하고 남은 금액만 개인 현금으로 지급한다.

### 6.2 신규 대출 규칙

| 항목 | 권장값 |
|---|---:|
| 담보인정비율 | 매입가와 시장가 중 낮은 값의 최대 60% |
| 고정 연이율 | 4.8% |
| 월 이자율 | 0.4% |
| 만기 | 24게임개월 |
| 상환 방식 | 매월 이자, 만기 원금 상환 또는 재심사 |
| 중도상환 | 수수료 없이 일부·전액 가능 |

```text
대출원금 = min(매입가, 시장가) × 60%
필요현금 = 매입가 + 매수부대비용 - 대출원금
월이자 = ceil(남은원금 × 0.004)
```

### 6.3 한도 판정

평판을 금액으로 바꾸는 현재 대출 한도 공식을 제거한다. 신규 건물의 예상 임대수입과 기존 채무를 사용한다.

```text
예상월순임대료 = 월세 × 예상입주율 75% × 운영비차감 90%
DSCR = 예상월순임대료 / 월이자
```

신규 담보대출은 다음을 모두 만족해야 한다.

- 계약금과 부대비용을 개인 현금으로 낼 수 있음
- 대상 건물 DSCR 1.20 이상
- 전체 월 이자 합계가 최근 3개월 평균 반복수입의 60% 이하
- 연체 중인 대출 없음

### 6.4 연체

잔액이 부족할 때 현금을 음수로 만들지 않는다.

1. 미납액을 기록하고 해당 대출을 1개월 연체로 표시한다.
2. 연체 중에는 신규 대출과 고가 소비를 제한한다.
3. 2개월 연속 연체 시 담보 건물을 시장가의 90%에 강제매각한다.
4. 매각대금으로 원금과 미납이자를 갚고 잔액을 지급한다.
5. 매각대금이 부족하면 남은 채무를 별도 미상환 채무로 유지한다.

평판 절반 감소는 제거한다. 채무 불이행의 결과는 자산과 신용 상태로 나타내는 편이 이해하기 쉽다.

## 7. 평판 재설계

### 7.1 역할

평판은 돈의 크기가 아니라 임대관리, 거래 신뢰, 사회활동의 누적 결과다. 자산 규모는 순자산이 담당한다.

### 7.2 권장 해금값

| 단계 | 평판 | 단계 | 평판 |
|---|---:|---|---:|
| 청주 1 | 0 | 대전 1 | 1,725 |
| 청주 2 | 40 | 대전 2 | 2,250 |
| 청주 3 | 90 | 대전 3 | 2,850 |
| 청주 4 | 190 | 대전 4 | 3,600 |
| 세종 1 | 375 | 부산 1 | 4,500 |
| 세종 2 | 600 + 퇴사 | 부산 2 | 5,625 |
| 세종 3 | 900 | 부산 3 | 6,750 |
| 세종 4 | 1,275 | 부산 4 | 8,250 |
| 인천 1 | 10,125 | 서울 1 | 19,500 |
| 인천 2 | 12,000 | 서울 2 | 22,500 |
| 인천 3 | 14,250 | 서울 3 | 26,250 |
| 인천 4 | 16,875 | 서울 4 | 31,500 |
| 기업가 자격 | 37,500 |  |  |

### 7.3 획득 경로

- 입주 건물 월 정산: 건물당 2~4
- 수리 요청을 한 달 안에 해결: 5
- 최초 단계 건물 구매: 단계별 20~1,500의 일회성 보상
- 비서 요청 해결: 100~2,000의 일회성 보상
- 기부 누적 이정표: 일회성 보상
- 사치품 최초 구매: 아이템별 고정 보상
- 주식 투자 원칙 이벤트, 기업 실적 이벤트: 후반 평판

최초 건물 구매 보상은 다음 값을 사용한다. 이미 보유한 단계는 저장 데이터 이전 때 수령 완료로 표시해 재구매 보상을 막는다.

| 도시 | 1번 | 2번 | 3번 | 4번 |
|---|---:|---:|---:|---:|
| 청주 | 0 | 50 | 100 | 180 |
| 세종 | 220 | 300 | 375 | 450 |
| 대전 | 525 | 600 | 750 | 900 |
| 부산 | 1,100 | 1,200 | 1,500 | 1,800 |
| 인천 | 1,875 | 2,250 | 2,625 | 3,000 |
| 서울 | 3,000 | 3,750 | 4,500 | 6,000 |

비서 고용 완료 보상은 1번부터 각각 100, 300, 600, 1,000, 1,500, 2,000이다.

반복 기부로 평판을 무한 구매하는 기능은 제거한다. 기부는 누적 금액 이정표로 바꾼다.

| 누적 기부액 | 평판 보상 |
|---:|---:|
| 100만원 | 20 |
| 1,000만원 | 100 |
| 1억원 | 500 |
| 10억원 | 2,000 |
| 100억원 | 6,000 |

각 이정표는 한 번만 지급한다. 이 구조에서는 돈이 도움이 되지만 평판 전체를 대체하지 못한다.

### 7.4 칭호

`대한민국 상위 N%`, `1조클럽`처럼 외부 사실을 단정하는 칭호는 평판 목록에서 제거한다. 자산 조건 칭호는 별도로 계산한다.

예시:

- 평판 칭호: `초보 임대인`, `지역 임대사업자`, `전문 자산관리자`, `자본시장 투자자`
- 순자산 업적: `100억 자산가`, `1,000억 자산가`, `1조 자산가`
- 지분 업적: `주요주주`, `최대주주`, `지배주주`

## 8. 비서와 소비

### 8.1 비서 월급

모든 비서는 같은 숙련도 월급 곡선을 사용한다. 고용 시점의 실제 월급은 각 비서의 초기 숙련도로 결정된다.

```text
숙련도 월급 = 150만원 + (1,750만원 - 150만원) × ((숙련도 - 1)² / 29²)
```

숙련도 1은 월 150만원, 숙련도 30은 월 1,750만원이다. 여섯 명이 모두 최대 숙련도일 때 총월급은 1억 500만원이다.

월급을 못 내면 현금을 음수로 만들지 않는다. 1개월 미납 시 효과 정지, 2개월 연속 미납 시 자동 해고가 권장된다.

### 8.2 선물

호감도 경험치 공식은 유지하고 가격만 다음처럼 조정한다.

| 선물 | 변경 전 | 적용 가격 |
|---|---:|---:|
| 고급 원두세트 | 15만원 | 15만원 |
| 만년필 | 100만원 | 50만원 |
| 프리미엄 향수 | 500만원 | 250만원 |
| 최고급 보석 | 3,000만원 | 1,250만원 |
| 인센티브 | 5억원 | 5,000만원 |

비서 한 명을 호감도 1에서 30까지 올리는 총비용은 77억 6,125만원, 여섯 명은 465억 6,750만원이다.

### 8.3 사치품

가격은 현재 범위를 대체로 유지한다. 다만 이름과 평판 보상을 정리한다.

- `그렌져`는 `그랜저`로 수정
- 사치품 평판은 `floor(가격 / 30만원 × 1.5)`로 계산
- 전용기 보유는 구매가격 외에 유지비를 월 정산에 추가

적용 평판 보상은 자전거부터 차례로 1, 150, 250, 350, 1,500, 10,000, 40,000, 125,000이다.

사치품은 부를 만드는 투자가 아니라 현금을 명예와 수집으로 전환하는 선택이어야 한다.

### 8.4 비서 임차인 이벤트 금액

부동산과 평판 기준이 바뀌므로 기존 이벤트 조건도 같은 배포에서 바꾼다.

| 비서 | 요청 가능 조건 | 실제 지출·완료 조건 |
|---|---|---|
| 1 | 현금 1억원 최초 달성 | 월세 두 달 감면 후 60일 경과 |
| 2 | 평판 1,275, 현금 3억원 | 1억원 지급 |
| 3 | 평판 3,600, 그랜저 보유 | 관리 견습 30일 경과 |
| 4 | 평판 8,250, 현금 150억원 | 위약금 60억원 지급 |
| 5 | 평판 12,000, 현금 800억원, 연체 없음 | 사업자금 300억원 지급 |
| 6 | 모든 사치품 보유, 현금 1,500억원 | 서울 4번 건물 구매 및 거주 제공 |

비서 6 이벤트는 부동산 서사의 종결 조건이다. 기업 설립 조건으로 재사용하지 않는다. 기업 콘텐츠는 9.3의 금융 조건을 독립적으로 판정한다.

## 9. 주식계좌 재설계

### 9.1 코인 폐지

`coin`을 `securitiesCash`로 바꾸고 단위를 원으로 통일한다.

```text
개인현금 1억원 입금 -> 증권계좌 예수금 1억원
증권계좌 예수금 1억원 출금 -> 개인현금 1억원
```

수수료는 매수·매도 각각 0.25%이며 화면에는 원 단위로 표시한다. 기존 주가 1만 9천~11만 8천이라는 숫자는 원 단위 주가로 그대로 사용할 수 있다.

### 9.2 주식 해금

부산 후반부 단계에서 다음 두 조건을 만족하면 `증권계좌 개설 제안` 이벤트를 예약한다.

- 순자산 300억원 이상
- 평판 8,250 이상

평판 8,250은 부산 4번 건물 해금과 같은 값이다. 부동산이 끝난 뒤 갑자기 주식이 나타나는 대신 부산 후반부터 포트폴리오 분산 수단으로 경험하게 한다.

### 9.3 기업 설립 진입

> 이 절의 기업 설립 수치는 폐기되었다. 최신 기준은 `PLAYER_COMPANY_V1_DESIGN.md` 2장과 9장을 따른다.

기업 설립은 부동산 보유나 특정 도시를 요구하지 않는다.

- 평판 37,500 이상
- 증권계좌 예수금 + 보유주식 평가액 500억원 이상
- 주식시장 해금 후 12게임개월 경과
- 최근 6게임개월 안에 강제매각 또는 대출 연체 없음
- 최소 출자금 100억원

부동산은 이 조건을 달성하기 위한 초기 자금 원천일 수 있지만 회사의 자산이나 매출 조건으로 들어가지 않는다.

## 10. 진행 단계

다음 시간은 구현 후 시뮬레이션으로 조정할 권장 목표다. 한 게임월은 약 2분 30초지만 이벤트 정지와 사용자 조작 시간은 포함하지 않는다.

| 구간 | 목표 게임월 | 핵심 행동 |
|---|---:|---|
| 청주 | 0~12 | 월급, 첫 임대, 소형 부동산 |
| 세종 | 12~30 | 퇴사, 다주택, 첫 비서 운영 |
| 대전 | 30~55 | 상가·다가구, 대출 관리 |
| 부산 | 55~85 | 상업용 부동산, 현금흐름 확대 |
| 인천 | 85~120 | 대형 자산, 증권계좌 해금 준비 |
| 서울·주식 | 110~170 | 대형 빌딩과 금융자산 병행 |
| 기업 설립 | 150~220 | 출자, 경영 시작 |
| 지주회사 | 기업 설립 이후 | 자회사·지분·인수 |

주식과 부동산 구간은 의도적으로 겹친다. 콘텐츠가 완전히 교대하면 기존 부동산이 즉시 쓸모없어지기 때문이다.

## 11. 기존 저장 데이터 이전

### 11.1 기본 원칙

- 저장 초기화 금지
- 한 번만 실행되는 `economyVersion` 사용
- 전체 이전을 하나의 트랜잭션으로 실행
- 이전 전 DB 백업 생성
- 실패 시 버전 값을 올리지 않음

### 11.2 건물

도시와 슬롯으로 새 카탈로그를 찾는다.

```text
기존매입비율 = 기존 purchasePrice / 기존 marketPrice
새 purchasePrice = 새 marketPrice × 기존매입비율
새 monthlyRent = 새 카탈로그 월세
```

이렇게 하면 저평가·고평가에 샀던 이력은 보존된다. 슬롯이 없는 구형 건물은 이름과 기존 가격으로 슬롯을 먼저 복구한다.

### 11.3 개인 현금

초반 금액은 유지하고 후반만 압축한다. 아래 기준점을 선형 보간한다.

| 기존 현금 | 이전 현금 |
|---:|---:|
| 0 | 0 |
| 10억원 | 10억원 |
| 100억원 | 100억원 |
| 1,000억원 | 700억원 |
| 5,000억원 | 1,400억원 |
| 1조원 | 1,800억원 |
| 3조 5,000억원 | 3,300억원 |
| 10조원 | 4,500억원 |

단일 비율을 쓰지 않는 이유는 초반 부동산 가격은 거의 유지하지만 서울 최고 자산은 10조원에서 4,500억원으로 크게 바뀌기 때문이다.

### 11.4 평판

기존 숫자를 단순 나눗셈하지 않는다. 기존 플레이어가 속한 해금 단계와 다음 단계까지의 진행률을 새 평판 구간에 옮긴다.

```text
구간진행률 = (기존평판 - 기존단계최소) / (기존다음단계 - 기존단계최소)
새평판 = 새단계최소 + 구간진행률 × (새다음단계 - 새단계최소)
```

이전 전후에 같은 도시와 같은 슬롯이 해금되어야 한다.

### 11.5 주식

기존 1코인 100원의 경제가치를 보존하면서 현재 주가 숫자를 원 단위로 사용한다.

```text
새 증권예수금 = 기존 coin × 100
새 보유수량 = 기존 quantity × 100
새 평균단가 = 기존 averagePrice 유지
새 가격이력 = 기존 가격 유지
```

따라서 이전 전 가치 `수량 × 가격 × 100원`과 이전 후 가치 `수량 × 100 × 가격원`이 정확히 같다.

거래 이력은 수량, 총거래액, 수수료, 정산액을 각각 100배하고 주당 가격은 유지한다.

### 11.6 대출

기존 대출에는 건물 외래키가 없다. 플레이어별로 `대출원금 / 60%`와 매입가가 가장 가까운 무담보 건물을 연결한다. 연결할 건물이 없으면 `LEGACY_UNSECURED` 상태로 옮기고 신규 대출과 분리한다.

기존 원금은 연결된 건물의 기존가격 대비 비율을 새 건물가격에 적용한다. 이전 직후 한 달은 이자 유예기간을 주고 화면에 새 상환 규칙을 안내한다.

## 13. 검증 기준

### 13.1 불변 조건 테스트

- 어떤 자동 정산도 개인 현금을 음수로 만들지 않는다.
- 건물 매각 시 담보대출이 남지 않는다.
- 대출원금보다 많은 원금을 상환할 수 없다.
- 증권계좌 입출금 전후 개인 총현금은 수수료가 없다면 동일하다.
- 주식 이전 전후 평가액은 정확히 동일하다.
- 평판 이전 전후 해금 슬롯은 동일하다.
- 경제 이전을 두 번 실행해도 두 번째 실행은 값을 바꾸지 않는다.
- 순자산은 자산 합계에서 부채를 정확히 한 번만 차감한다.

### 13.2 시뮬레이션

고정 시드 1만 회 몬테카를로 시뮬레이션을 만든다. 최소 세 전략을 비교한다.

- [x] 고정 시드 1만 회 시뮬레이터 구현
- [x] 무대출 안정형
- [x] 60% 대출 성장형
- [x] 매매·경매 적극형

각 전략에서 다음 값을 기록한다.

- 도시별 첫 해금 게임월의 중앙값, 10·90백분위
- 현금이 부족한 월 수
- 강제매각 비율
- 최고 순자산과 구성비
- 주식 해금과 기업 설립 시점
- 총수입 중 월급, 임대, 매매차익, 주식손익의 비율

합격 기준은 아직 충족하지 못했다.

- [ ] 정상적인 대출 성장형의 기업 설립 중앙값이 150~220게임월
- [ ] 동일 전략 90백분위가 중앙값의 2배를 넘지 않음
- [ ] 경매만 반복한 전략이 정상 임대 전략보다 2배 이상 빠르지 않음
- [x] 매매차익이 전체 부의 50%를 지속적으로 넘지 않음 (적극형 44.1%)
- [ ] 후반 순자산에서 단일 건물 비중이 60%를 넘지 않음
- [ ] 파산은 잘못된 채무 관리 결과로만 발생하고 랜덤 이벤트 한 번으로 발생하지 않음

## 14. 이번 설계에서 보류할 것

다음 기능은 경제 기준표가 안정된 뒤 추가한다.

- 실제 세율을 모사한 복잡한 세금
- 물가상승률과 화폐가치 하락
- 지역별 실거래가 데이터 연동
- 변동금리와 신용등급별 가산금리
- 부동산 개발·재건축
- 기업의 부동산 보유

현재 필요한 것은 숫자를 더 늘리는 기능이 아니라 원화, 자산, 부채, 현금흐름의 의미를 일관되게 만드는 것이다.
