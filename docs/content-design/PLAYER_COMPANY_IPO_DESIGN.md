# 플레이어 기업 IPO 1차 설계

> 상태: 기업 운영 코어와 주식 V2 구현을 대조한 후 작성한 후속 설계
> 범위: IPO 준비, 신주 공모, 플레이어 기업의 주식시장 편입, 상장 후 실적·뉴스·배당 연결
> 제외: 인수합병, 지주회사, 적대적 M&A, 상장폐지, 반복 증자

## 1. 목적

IPO는 기업 콘텐츠의 종료 보상이 아니라 기업 운영과 주식 콘텐츠를 연결하는 선택형 후반 목표다.

- 비상장을 유지하면 지분과 경영 자유를 보존한다.
- 상장하면 대규모 법인자금과 인지도를 얻지만 플레이어 지분이 희석되고 공시 의무가 생긴다.
- 상장 이후에도 기업 운영은 계속한다.
- 별도의 수요예측 미니게임을 만들지 않고 경영 판단에 필요한 조건과 결과만 제공한다.

### 플레이어 보상과 반대급부

- IPO의 직접 보상은 신주 공모대금이 법인현금으로 들어오는 대규모 성장자금이다.
- 공모대금은 개인현금으로 지급하지 않는다. 개인·법인 자금 분리와 기업 운영의 의미를 유지하기 위함이다.
- 보조 보상은 상장기업 신뢰도에 따른 대형·전략계약 조건 개선과 회사채 조건 개선으로 제한한다.
  두 효과는 주식 연결 이후 별도 수치 검증을 거쳐 소폭 적용하며, IPO가 무조건 정답이 될 정도로 중첩하지 않는다.
- 반대급부는 플레이어 지분 희석, 외부 주주 배당 부담, 실적·악재의 시장 공개와 향후 경영권 제약이다.
- 창업자 지분을 즉시 매각해 개인현금을 얻는 기능은 초기 IPO 범위에서 제외한다.

## 2. 현재 구조 점검

### 이미 사용할 수 있는 구조

- `PlayerCompany`는 발행주식, 플레이어 주식과 지분율을 저장한다.
- 초기 발행주식은 1,000만주이며 설립 시 플레이어가 100% 보유한다.
- `ListedCompany`, `StockPriceHistory`, `OwnedStock`은 플레이어와 `stockKey`를 함께 저장한다.
- 기업 분기보고, 기업가치, 배당, 기업뉴스는 실제 기업 운영 결과로 생성된다.

### IPO 전에 보완할 구조

- 현재 `StockCatalog`는 NPC 15개 종목만 반환한다.
- 가격 갱신, 유동성, 차트와 종목 화면도 고정 카탈로그를 직접 순회한다.
- NPC 상장기업 재무는 별도의 자동 시뮬레이션으로 생성된다.
- 플레이어 기업을 NPC 재무 갱신에 넣으면 실제 기업 실적과 가상 실적이 중복된다.
- 종합지수는 구성 종목의 기준 시가총액을 매번 다시 가중하므로 신규 종목을 즉시 편입하면 지수가
  구성 변경만으로 움직일 수 있다.

따라서 고정 카탈로그를 수정하는 대신 플레이어별 거래 가능 종목을 제공하는 동적 종목 공급 계층을
추가한다.

## 3. IPO 신청 조건

대기업 단계는 신청 필수조건으로 사용하지 않는다. 실제 서비스 72개월 검증에서 정상 운영 기업도
성장기업 단계였으므로 대기업을 강제하면 IPO가 과도하게 늦어진다.

다음 조건을 모두 충족하면 신청할 수 있다.

| 조건 | 기준 | 이유 |
| --- | ---: | --- |
| 기업 단계 | 성장기업 이상 | 프로 요금제와 정식 조직을 운영한 이후 개방 |
| 운영 기간 | 확정 분기보고 8개 이상 | 최소 2년의 공개 가능한 실적 확보 |
| 수익성 | 최근 2개 분기 연속 영업흑자 | 일회성 흑자로 상장하는 것을 방지 |
| 월 반복매출 | 300억원 이상 | 상장 후 지속 매출 기반 확인 |
| 유료 이용자 | 100만명 이상 | 시장성 확인 |
| AI 벤치마크 | 400점 이상 | 기술기업으로서 최소 경쟁력 확인 |
| 최근 확정 지분가치 | 3조원 이상 | 기존 주식시장과 비교 가능한 규모 확보 |
| 전략재무팀 | 출범·전문성 60 이상 | IPO 분석과 공시 담당 부서에 실질적 역할 부여 |
| 재무 상태 | 운영중단·미지급금·채권 연체 없음 | 상장 직전 지급불능 상태 차단 |
| 서비스 상태 | 미처리 치명 장애 없음 | 중대한 운영 위험을 숨긴 채 상장하는 상황 차단 |

정상 상환 중인 회사채와 진행 중인 일반 프로젝트는 IPO를 막지 않는다. 신청 화면에는 충족·미충족
조건과 현재값을 모두 표시한다.

## 4. 준비 절차

```text
비상장
→ IPO 신청 및 공모비율 선택
→ 준비비 120억원 지급
→ 6개월 준비
→ 최종 자격 재심사
→ 신주 발행과 공모대금 납입
→ 주식시장 상장
```

- 준비비 120억원은 신청 시 법인현금에서 한 번 차감한다.
- IPO 준비는 전략재무팀 주요 업무 슬롯 1개와 전사 주요 업무 슬롯 1개를 6개월간 사용한다.
- 기업 운영이 중단되면 준비기간 진행도 함께 정지한다.
- 준비 중 신청 조건이 일시적으로 깨져도 즉시 실패시키지 않는다.
- 6개월 종료 시 최종 조건을 다시 검사하고 미충족이면 준비 완료 상태로 대기한다.
- 조건을 회복하면 별도 비용 없이 상장을 확정할 수 있다.
- IPO 신청 취소 시 이미 지출한 준비비는 반환하지 않는다.

## 5. 공모비율과 공모가

IPO는 구주매출 없이 신주만 발행한다. 공모대금 전액은 법인현금으로 들어간다.

공모비율은 상장 후 전체 발행주식 중 신규 공모주가 차지하는 비율이다.

| 공모비율 | 특징 |
| ---: | --- |
| 15% | 조달금이 적지만 지분을 가장 많이 보존 |
| 25% | 조달금과 지분 희석의 균형안 |
| 35% | 조달금이 많지만 지분 희석과 경영 제약 위험이 큼 |

```text
신주 수
= 기존 발행주식 × 공모비율 / (100% - 공모비율)

기준 주당가치
= 상장 확정 시점의 최근 확정 지분가치 / 기존 발행주식

공모가
= 기준 주당가치 × 90%

공모대금
= 신주 수 × 공모가
```

- 신주 수는 공모비율 이상을 충족하는 최소 정수로 올림한다.
- 공모가는 100원 단위로 반올림하고 최소 1,000원으로 제한한다.
- 10% 공모 할인은 신규 상장 불확실성을 반영하며 별도 수요예측 확률을 대체한다.
- 상장 시점에 새 분기 가치가 확정되면 신청 당시 예상가가 아니라 최신 확정 가치를 사용한다.
- 화면에는 신청 시 예상 공모가·신주 수·조달금·상장 후 지분율을 범위가 아닌 확정 공식으로 표시한다.

### 예시

기존 발행주식 1,000만주, 플레이어 지분 100%, 최근 지분가치 3조원일 때 기준 주당가치는 30만원,
공모가는 27만원이다.

| 공모비율 | 신규 발행량 | 예상 조달금 | 상장 후 플레이어 지분 |
| ---: | ---: | ---: | ---: |
| 15% | 약 176만주 | 약 4,765억원 | 85% |
| 25% | 약 333만주 | 약 9,000억원 | 75% |
| 35% | 약 538만주 | 약 1조4,538억원 | 65% |

기존 외부지분이 10%라면 플레이어 지분은 각 선택에서 76.5%, 67.5%, 58.5%가 된다. IPO 결과
플레이어 지분이 20% 미만이 되는 선택은 허용하지 않는다.

## 6. 저장 모델

IPO 진행상태는 `PlayerCompany`에 필드를 계속 추가하지 않고 별도 `CompanyListing` 엔티티로 관리한다.

```text
CompanyListing
- company
- stockKey
- status: PREPARING / READY / LISTED / CANCELLED
- selectedOfferPercent
- applicationElapsedDay
- preparationMonthsCompleted
- preparationCost
- valuationAtListing
- offerPrice
- newShares
- proceeds
- listedElapsedDay
- quarterSequenceAtListing
- lastPricedQuarterSequence
```

- 플레이어 기업 내부 종목 키는 회사명과 무관한 `player-company` 고정값을 사용한다.
- 회사명이 바뀌어도 URL, 가격이력과 거래기록의 키는 바뀌지 않는다.
- 플레이어당 기업이 하나이므로 같은 키를 사용해도 플레이어 복합키에서 충돌하지 않는다.
- 신청, 비용 차감, 업무 슬롯 예약은 하나의 트랜잭션으로 처리한다.
- 상장 확정, 신주 발행, 법인현금 증가, 상장기업 생성과 첫 가격 저장도 하나의 트랜잭션으로 처리한다.
- 중복 요청 키와 현재 상태를 검사해 공모대금이 두 번 들어오지 않게 한다.

## 7. 주식 종목 공급 구조

`StockCatalog`는 기존 NPC 15개의 고정 정의만 계속 담당한다. 새 `StockUniverseService`가 화면과
가격 처리에 사용할 플레이어별 종목 목록을 제공한다.

```text
StockUniverseService.stocks(player)
= StockCatalog의 NPC 15개
+ 상장 완료된 플레이어 기업 1개
```

플레이어 기업의 동적 종목 정의:

| 항목 | 값 |
| --- | --- |
| stockKey | `player-company` |
| 회사명 | 실제 플레이어 회사명 |
| 업종 | IT |
| 위험등급 | 공격 |
| 시장 베타 | 1.25 |
| 업종 민감도 | 1.15 |
| 고유 변동성 | 2.20% |
| 기준가 | 확정 공모가 |
| 발행주식 | IPO 후 실제 발행주식 |
| 설명 | 실제 서비스명과 기업 단계 기반 문구 |

초기 IPO 범위에서는 베타를 매달 바꾸지 않는다. 성장단계별 동적 베타는 플레이어에게 의미가 불분명하고
가격 원인 분석을 어렵게 하므로 제외한다.

## 8. 실적과 적정가치 연결

플레이어 기업은 NPC 기업 재무 시뮬레이션에서 제외한다.

- 분기 매출·영업이익·순이익: `CompanyQuarterlyReport`
- 현금: `PlayerCompany.corporateCash`
- 부채: 미상환 회사채와 미지급금
- 적정 지분가치: `CompanyValuationSnapshot`의 최근 확정 가치
- 적정 주가: 최근 확정 지분가치 / IPO 후 발행주식
- 실적 예상 대비: 이전 분기 추세와 전략재무팀의 기존 전망값 사용
- 배당: `CompanyFinanceService`에서 결정한 실제 기업 배당 사용

현재 코드의 `enterpriseValue` 명칭은 현금과 부채를 반영한 계산 결과이므로 IPO에서는 경제적으로
pre-money 지분가치로 해석한다. 공모가 계산에서 부채를 다시 차감하지 않는다.

NPC 재무와 플레이어 기업 재무를 같은 타입으로 화면에 공급하기 위해 `StockFinancialDataService`
경계를 둔다. NPC는 기존 `ListedCompany` 재무를, 플레이어 기업은 실제 기업 보고서를 사용한다.

## 9. 상장 후 가격

- 첫 캔들은 상장일 공모가로 생성한다.
- 상장 전 과거 캔들은 만들지 않는다.
- 이후 기존 주식과 같은 5일 주기로 가격을 갱신한다.
- 시장 국면, IT 업종 영향, 실제 기업뉴스와 실적 충격을 기존 주가 V2에 입력한다.
- 가치회귀 기준은 고정 공모가가 아니라 최근 확정 적정 주가다.
- 분기 가치가 확정될 때 적정 주가 기준도 갱신한다.
- 기업 운영 결정 자체는 즉시 주가를 움직이지 않고, 결과가 뉴스·실적에 확정될 때 반영한다.

## 10. 종합지수 처리

플레이어 기업은 IPO 직후 종합지수에 편입하지 않는다.

NPC와 플레이어 기업 모두 상장 이후 실제 분기 실적 2개가 확정되면 다음 주가 갱신일부터 자동 편입한다.
플레이어 기업은 IPO 당시 이미 존재하던 분기보고서를 세지 않고 IPO 이후 확정된 보고서만 센다.
편입일에는 직전 지수에 새 구성 종목의 5일 수익률을 연결해 구성 변경만으로 지수가 움직이지 않게 하며,
단일 종목 비중 상한 15%를 동일하게 적용한다. 종목 교체·상장폐지는 현재 범위에서 제외한다.

## 11. 플레이어 보유지분과 거래

- 플레이어의 기존 주식은 창업자 지분으로 유지한다.
- 창업자 지분을 `OwnedStock`으로 옮기지 않는다.
- 상장 후 회사 화면과 주식 상세에 지분율·주식 수·시장가치를 표시한다.
- 창업자 지분가치는 현금이나 주식 매수 가능금액에 포함하지 않는다.
- 기존 도시·주식 해금에 사용하는 순자산 계산에도 포함하지 않는다.
- 초기 IPO 범위에서는 플레이어가 자기 회사 종목을 개인 증권계좌로 추가 매수·매도하지 못한다.

자기 회사 거래를 허용하면 내부자 거래기간, 창업자 보호예수, 지분 매각에 따른 경영권 변화와 배당 중복을
같이 구현해야 한다. 이는 IPO 핵심 연결보다 범위가 크므로 후속 지분거래 단계로 미룬다.

## 12. 뉴스와 화면

기업 화면:

- IPO 조건 현황
- 준비 진행도와 남은 개월
- 예상 공모가·조달금·상장 후 지분
- 최종 상장 확정 명령

기업뉴스:

IPO 팝업은 실행 전 준비기간, 준비비, 공모비율, 예상 조달금, 예상 지분율과 주요 위험을 모두 보여준다.

## 15. 구현 현황

### 1단계 완료

- `CompanyListing` 엔티티와 `CompanyListingStatus`를 추가했다.

### 2단계 완료

- 6개월이 지나면 `READY`로 전환하고 운영조건을 다시 검사한다. 조건을 잃었더라도 신청을
  실패시키지 않고 회복을 기다린다.

  재신청해도 거래원장 키가 충돌하지 않는다.
- HTTP 명령은 `/companies/ipo`, `/companies/ipo/cancel`, `/companies/ipo/confirm`으로 분리했다.
  화면 연결은 IPO 패널 구현 때 진행한다.

- 준비 완료 후 최신 확정 지분가치로 공모가·신주·조달금을 다시 계산하는 상장 확정 트랜잭션을
  구현했다.
- 기존 플레이어 보유분은 창업자 지분, 기존 외부지분은 기관 지분, IPO 신주는 시장 유통분으로
  분리해 발행주식 합계를 보존한다.
- 신주 발행, 공모대금 법인 원장 입금, `ListedCompany` 생성, 첫 공모가 캔들 저장, IPO 상태 완료와
  업무 슬롯 반환은 한 트랜잭션으로 처리한다.
- 상장 후 플레이어 지분이 20% 미만이면 최종 확정을 거부한다.

### 4단계 완료·5단계 완료

- `StockFinancialDataService`가 NPC 재무와 플레이어 기업의 실제 분기보고·기업가치·현금·부채를

- 차트 실적·배당 마커는 상장 후 공개된 실제 `CompanyQuarterlyReport`만 사용한다.

- 자기 회사 주식 매수·매도는 화면 계산과 서버 명령에서 모두 0주·거래불가로 제한한다.
- 상장 후 발생한 제품 개선, 연산설비 완공, 서비스 장애, 외부 시장사건과 확정 실적을 주식 뉴스 피드로

  충격으로 반영되므로 뉴스 가격 영향은 0으로 두어 중복 계산을 막는다.

- 기업 배당은 기존 `CompanyFinanceService`가 법인현금 차감과 창업자 몫의 개인현금 지급을 계속
  담당한다. 주식 연결부는 별도 배당금을 지급하지 않는다.
- 상장기업의 실제 배당총액을 발행주식으로 나눈 주당배당만큼 최신 주가에 배당락을 적용하고,
  배당 결정 공시와 주식 상세의 최근 주당배당·배당성향을 실제 분기보고에서 표시한다.
- 실적 발표일과 배당 결정일을 별도로 저장해 차트의 실적·배당 마커가 각 실제 결정 시점에 표시된다.
- 무배당 결정도 공시하지만 가격은 조정하지 않는다.

- 준비 중에는 정상 월 정산 기준 진행 개월을 표시하며 취소할 수 있다. 6개월 완료 후 최종 조건을

- 상장 완료 후에는 확정 공모가, 조달금, 현재 창업자 지분과 주식 화면 이동 명령을 표시한다.

  창업자 지분 관리 안내를 제공한다.

### 7단계 완료: IPO 통합 검증

- 격리된 H2 데이터베이스에서 성장기업, 8개 분기보고서, 전략재무 전문성, 기업가치 등 실제 IPO 자격 판정을 구성했다.
- 25% 공모 신청, 준비비 차감, 정상 결산 6회, 최종 상장, 신주 발행, 법인 조달금 입금과 최초 공모가 저장을 한 경로로 검증했다.
- 상장 후 기업 화면의 주식시장 이동 링크와 주식 화면의 `내 기업` 표시를 검증했다.
- 자기 회사 주식의 매수·매도 폼이 렌더링되지 않는 것도 함께 검증했다.
- 통합 테스트에서 동적 종목이 NPC 전용 재무 카탈로그 초기화를 통과하며 예외가 발생하는 문제를 발견했다.
  NPC 재무 서비스는 카탈로그가 직접 관리하는 고정 종목만 기준실적 생성과 분기결산 대상으로 삼도록 수정했다.

### 8단계 완료: 실제 화면 종합 검증

- 기존 QA 계정에서 IPO 자격 충족, 25% 공모 신청, 준비 상태, 상장 확정과 주식시장 이동을 실제 화면으로 검증했다.
- 신청 시 준비비 차감과 전사·전략재무 주요 업무 슬롯 예약, 상장 후 슬롯 반환과 법인 조달금 입금을 확인했다.
- 기업 상단의 발행주식과 플레이어 지분이 상장 후에도 고정값으로 남는 문제를 수정해 실제 발행주식과 지분율을 표시한다.
- 주식 화면에서 플레이어 기업의 공모가 캔들, 시가총액, 창업자 지분, 실제 분기실적과 자기 회사 거래 제한을 확인했다.
- 상장 후 25% 배당을 실제 화면에서 결의해 개인 배당금 지급, 배당 결정 공시, 주당배당·배당성향·예상배당금 반영을 확인했다.
- 배당 확인창이 같은 재무 패널의 회사채 기간과 이자를 잘못 표시하던 문제를 수정해 배당금, 담당 부서와 배당 영향을 표시한다.
- IPO 신청과 준비 완료는 상장 전 기업 재무뉴스로 각각 한 번 기록한다.
- 상장 완료는 확정 공모가·신주·법인 조달금을 포함한 기업뉴스로 기록하고 주식 뉴스에도 중립 공시로 한 번 전달한다.
- IPO 뉴스는 신청 차수를 사건 키에 포함해 취소 후 재신청을 구분하며, 같은 상태의 중복 요청은 추가 기사를 만들지 않는다.

### 120개월 시뮬레이션 결과

밸런스 수치는 아직 변경하지 않았다.

- 권장 출자금과 기존 균형 의사결정을 사용한 경로는 79개월 차에 법인 현금이 고갈됐다.
  당시 월 반복매출은 약 399억원, 유료 이용자는 1,050,692명, 벤치마크는 471점이었고 IPO 신청 전이었다.
- 현금 런웨이 6개월 미만에서 기업가치의 10% 회사채를 발행하고 저현금 구간의 신규 제품 투자를 멈춘 경로는
  84개월 차 회사채 만기 원금을 감당하지 못해 운영이 중단됐다.
  당시 법인 현금은 약 516억원, 미지급액은 약 1,001억원, 월 반복매출은 약 435억원,
  유료 이용자는 1,143,763명, 벤치마크는 371점이었고 IPO 신청 전이었다.

후속 검증에서는 공격적 출자금 1조2,000억원을 사용하고, 연산용량 부족과 서비스운영팀 처리한도 부족을
분리해 대응했다. 중형 연산망 기반 구축 후 스타터 클라우드로 하향한 결과 120개월 동안 운영중단 없이
생존했으며 최종 법인현금은 약 6,526억원, 최저 법인현금은 약 4,234억원이었다. 회사채를 발행하지
않고도 경로가 성립했으므로 회사채 24개월 만기와 이자율은 변경하지 않는다.

다만 이 자연 운영 경로의 120개월 시점 기업가치는 IPO 최소 기준을 충족하지 못했다. 따라서 이번
검증은 장기 생존성과 인프라 전환만 확정하며, IPO 신청 시점과 공모 조달금은 별도의 성장·가치 경로로
검증한다. 이 결과만으로 IPO 조건을 낮추지 않는다.

### 240개월 자연 도달성 검증

- 공격적 출자금 1조2,000억원과 실제 서비스 의사결정 경로에서 IPO 전체 조건은 63개월차에
  처음 동시에 충족됐다.
- 성장단계, 분기보고, 최근 흑자, 반복매출, 유료 이용자, 벤치마크, 전략재무 전문성은 각각 경로 중
  한 번 이상 기준에 도달했다.
- 경쟁사 장기 수렴식 적용 후 기업가치는 30개월차에 3조원을 넘었다.
- 성숙기 가치평가 보완 전 63개월차 기업가치는 1조7,903억원이었다. 보완 후에는 같은 시점에
  3조886억원으로 평가되어 기준을 충족했다.
- 63개월차 월 반복매출은 약 381억원, 유료 이용자는 1,003,898명, 벤치마크는 402점이었다.

성숙기 가치평가는 성장기업 4배를 기준으로 벤치마크 400점, 유료 이용자 100만명, 최근 2개 분기
흑자를 각각 1배씩 반영해 최대 7배를 적용한다. 매출 감소 시에는 기존 2배를 유지한다. 이 방식으로
IPO 기업가치 기준 3조원을 낮추지 않고 성장 둔화에 따른 가치 급락만 보완했다.

63개월차 예상 공모가는 34,700원이며 예상 조달금은 15% 약 4,899억원, 25% 약 9,253억원,
35% 약 1조4,948억원이다. 공모 후 플레이어 지분은 약 85%, 75%, 65%다.

경쟁사 기본 성장식은 전략별 장기 목표에 수렴하도록 수정했다. 프론티어AI 2,600점, 모두AI
2,200점, 트러스트랩 2,400점을 넘지 않으며 목표에 가까울수록 분기 성장량이 감소한다.

### 9단계 완료: 상장 후 제한적 운영 혜택

- 상장 완료 후 새로 발행하는 회사채의 월 이자율은 비상장 기준 0.50%에서 0.45%로 낮아진다.
- 상장 완료 후 새로 생성되는 대형 계약은 벤치마크 10점, 안정성·보안 2점씩 심사 기준이 완화된다.
- 상장 완료 후 새로 생성되는 전략 계약은 벤치마크 20점, 안정성·보안 3점씩 심사 기준이 완화된다.
- 시험·일반 계약, 계약 제안 확률, 수익, 구축 업무량, SLA, 회사채 한도와 24개월 만기는 바꾸지 않는다.
- 이미 발행한 회사채와 이미 생성된 계약 제안은 저장 당시 조건을 유지한다. 상장 혜택을 소급하면
  기존 결산과 플레이어가 확인한 계약 조건이 달라지기 때문이다.
- 재무 화면에는 현재 회사채 월 이자율과 상장 신뢰도 적용 여부를 명시한다.

### 10단계 완료: 미출범 기업 조회 안전성

- 전략재무팀이 아직 출범하지 않은 기업은 IPO 전략재무 조건을 현재값 0으로 표시한다.
- IPO 화면 조회 시 존재하지 않는 전략재무팀의 업무 슬롯을 조회하지 않으며, 업무 여력을 미충족으로
  표시한다.
- 이는 IPO 조건을 완화하지 않는다. 전략재무팀 출범과 전문성 60 이상 조건은 그대로 유지한다.

### 11단계 완료: 임시 조건 복구 전 최종 점검

- IPO 신청·준비·취소·최종 상장, 신주·공모대금·지분, 실제 실적·뉴스·배당·주가 연결을 다시
  대조했다.
- 전략재무팀 미출범 기업은 IPO 패널에서 조건과 업무 여력을 미충족으로 표시하며 화면 조회 중
  존재하지 않는 부서의 슬롯을 조회하지 않는다.
- 자기 회사 주식 매매 차단과 상장 직후 종합지수 미편입을 유지한다.
- NPC와 플레이어 기업 모두 상장 후 실제 분기 실적 2개가 확정되면 종합지수에 편입한다.
- 구주매출, 창업자 지분 매도, 보호예수, 반복 증자와 상장폐지는 초기 IPO 범위에 추가하지 않았다.
- 정보 화면에 실제 신청 기준, 120억원 준비비, 6개월 준비, 공모비율, 신주 공모, 상장 후 주식 연결과
  제한적 운영 혜택을 추가했다. 외부투자와 회사채 이자 안내도 현재 구현과 일치시켰다.
- 최종 설정 복구 후 전체 자동 테스트 240개를 통과했다.
- 기업 탭 상시 접근과 설립조건 우회를 제거했다. 상용화 즉시 완료 명령도 삭제했으며 남은 QA 명령은
  `qa` 프로필에서만 등록한다.

### 12단계 완료: IPO 사후 일관성 보완

- 상장 후 개인 유상증자는 기업 원장의 발행주식·플레이어 주식과 상장기업 주주명부의 발행주식·창업자
  주식을 같은 트랜잭션에서 함께 늘린다. 창업자 지분율과 시가총액의 기준 주식 수가 어긋나지 않는다.
- 동적 신규상장의 최초 공모가 캔들은 전체 시장의 공통 5일 갱신 기준일로 사용하지 않는다. 고정 NPC
  기준 종목의 최근 캔들만 시장 갱신 시계를 결정한다.
- 공모 후 플레이어 지분이 20% 미만이 되는 선택지는 신청 버튼에서 비활성화하며 서버 신청 단계에서도
  다시 거부한다.
- 자기 회사 주식 화면에 상장일, 공모가, 창업자 보유주식과 현재 지분가치를 표시한다.
- 상장 당시 마지막 배당 결정 분기를 별도로 저장한다. 같은 날 상장 후 결정된 신규 배당은 차트 사건으로
  표시하고, 상장 전에 이미 결정된 같은 날 배당은 제외한다.
